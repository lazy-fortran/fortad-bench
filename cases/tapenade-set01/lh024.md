# Tapenade set01 `lh024`: exact-source call-boundary refusal

The pinned source is valid fixed-form Fortran. `test` runs 100 in-place
iterations, calls `sub1(v1,x,y(i))`, and lets that call mutate both `x(15)` and
the actual `y(i)`. The stored primal, tangent, multidirectional tangent, and
reverse references are retained upstream and all compile strictly when the
multidirectional file receives Tapenade's checked-in `DIFFSIZES.f` as
`DIFFSIZES.inc`.

Fresh pinned Tapenade parser, tangent, and reverse generation also succeeds;
all three generated files compile with strict fixed-form GNU Fortran. FortAD's
exact-source forward and reverse attempts both stop at the same call-boundary
diagnostic because the mutating call actuals are not plain variables.

The case includes a bounded standard-conforming port. It keeps the update
order and `x(15)` side effect, but copies `y(i)` into a plain `yi` temporary
before calling the mutating helper. The port's FortAD forward transform passes
strict compilation and an independent hand JVP/VJP, central-difference sweep,
and adjoint identity. Its reverse transform reaches FortAD's separate
per-iteration-storage refusal for the in-place `x` loop. These results are
bounded evidence for the exact-source refusal boundary, not an exact-source
support claim.

Run:

```sh
FORTAD_REPO=../fortad TAPENADE_REPO=upstream/tapenade \
  scripts/bench_tapenade_set01_lh024.sh
```
