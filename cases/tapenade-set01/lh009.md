# Tapenade set01 `lh009`: invalid-source refusal

The pinned upstream candidate is `nonRegressions/set01/lh009/program.f`, whose
`cfgLoop1` routine declares `a` as both `REAL` and `CHARACTER`.  Its stored
Tapenade tangent and reverse references repeat that conflict.  With
`gfortran -std=f2018 -pedantic-errors -ffixed-line-length-none`, the exact
primal and both stored references are rejected; fresh pinned Tapenade parser,
tangent, and reverse output is generated, but each generated file is rejected
by the same strict compiler oracle.

`lh009.f90` is a standard-conforming bounded interpretation of the intended
array loop.  It is compiled only to run the independent hand primal/JVP/VJP
oracle, a central-difference sweep, and the adjoint identity.  The port is not
used to claim FortAD support, because repairing the upstream declaration would
change the exact candidate being classified.

Run the reproducible refusal evidence with:

```console
$ FORTAD_REPO=../fortad TAPENADE_REPO=upstream/tapenade \
    scripts/bench_tapenade_set01_lh009.sh
```

The runner requires FortAD `db00502` and Tapenade
`e59864cab441d4175df75383b3ff58c3dcd26df9`, records every expected strict
compile failure, and requires the independent oracle to pass.
