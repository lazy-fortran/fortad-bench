# Tapenade set01 `lh027`

The exact pinned source is the fixed-form `s1(a,b)` regression.  It updates
`a(i)` in place, increments positive `b(i)`, and jumps back to label 100 after
the nonpositive branch.  The stored reverse reference uses `INTEGER*4` and
Tapenade push/pop runtime calls; the multidirectional reference includes the
unavailable `DIFFSIZES.inc`.  Those exact references are retained as evidence,
not repaired.

The bounded port splits the overwritten arrays into `a_out` and `b_out`, and
adds the scalar objective `objective=sum(a_out)`.  It restricts the numerical
oracle to positive `a` and `b`.  On that fixed trace, `a_out(i)=a(i)b(i)` and
`b_out(i)=b(i)+1`; the hand array/scalar JVP/VJP, central differences, and
adjoint identity are independent of FortAD and Tapenade.

The runner checks every exact source and stored reference with strict fixed-form
flags, regenerates fresh pinned Tapenade parser/tangent/reverse files, and
strictly compiles those outputs.  It then checks FortAD JVP and VJP generation,
compilation, and runtime on the bounded port.  For completeness it probes the
exact source too: FortAD's exact forward output is generated but fails strict
compilation because the legacy control-flow normalization loses `i`; exact
reverse is refused with the pinned `assignment to undeclared ')'` diagnostic.
The exact forward output compiles, but its generated loop index is
uninitialized; it is therefore recorded as a diagnostic and is not used for a
runtime claim.
